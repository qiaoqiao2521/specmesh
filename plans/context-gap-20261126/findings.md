# Findings

- `scripts/retrieve_evidence.py` is already an explicit, read-only source command.
  It rebuilds Map v0 in memory, requires current spec/area bindings and returns
  separate code/history/control/Drive statuses.
- History joins require exact project/spec/area/commit and native
  source/store/session/index-revision identities. Only locators survive;
  `live_verified=false` is preserved. A query match is not task completion.
- Existing `docs/RETRIEVAL-CONTRACT.md` describes compression, recall, full case
  inspection and native materials. Its optional native test accepts a caller
  checkout via `AGENTTRACEMESH_CHECKOUT`; no runtime dependency is necessary.
- The new native check exercises the actual context command: a found case stays
  `needs_review`, the same receipt causes zero repeated retrieval calls, and a
  context receipt fails the unchanged materials schema validator. Full case
  expansion still exposes a later correction absent from compact candidates.
- `no_gap` reflects caller-declared needs, not automated semantic completeness.
  Receipt reuse depends on the caller's state revision; it does not independently
  discover live changes or prove that indexed history is fresh.
- The minimal missing layer is the caller's conditional retrieval rule and
  responsibility boundary, not a second index, memory store or state machine.
- Runtime version 1.3.0 and normative version 1.1.0 identify different products;
  this source clarification does not replace an already published archive.
- Optional external knowledge configuration is unavailable in this cloud task;
  repository sources suffice and no private knowledge store is required.
