# Findings

## 2026-11-23 correction

- 人的图谱不应被文本 token 预算呈现为没有关系的散点。实际完整 Map 在实现冻结时为 206 节点 / 206 关系；global 1200 选 62 节点却没有余量列关系。保留现有文本选择语义，页面显式提供完整图与预算选集两种范围；预算未含边时默认完整分组图，并保留聚焦标识。
- 发布前 Blender main 又前进到 770fcb0b，新增餐厅流程、陶艺构件/提示词和光照规则；已同步其全部变更，业务模型仍为 10 模块 / 15 关系 / 7 检查。本轮只改采用说明和可视化 CI。

- 最新 main@effe232 的构建结果带有 Map 关系，但 HTML 未读取 data.map；主图实际使用另一份模块声明。没有 architecture.json 时构建失败，说明它尚不是现有图谱的直接展示组件。
- 本仓原版无测试生成实测 0.216 秒；这个数字仅说明该工作区一次静态构建，不代表运行检查或历史快照的成本。
- 现有 render_view 已包含排名、配置关系捆绑、area 门禁和预算，应提取同一个选择函数给文本/HTML使用，避免写第二套查询逻辑。
- Blender main 已推进到 f7bdd188，新增六阶段流程、10 个业务模块和 7 项检查；本轮在其上同步，保留新增模块、场景规则与生产代码。
- 当前 Blender 本地稀疏检出只物化相关文本。完整 Git 基线不能直接与局部工作区比较后声称文件删除；比较必须明确 unavailable，完整 CI 检出另行验证。

- Map v0 已实现 code/mem/spec、内容指纹和 current-only area 注入；无需另建索引。
- 当前独立运行时 ZIP 是明确允许列表；人用 Explorer 属于可选源码工具，不更新规范版本或历史发行包。
- 自动扫描能够确认文件/符号存在，不能证明业务依赖与任务验收。关系来自 reviewed JSON，结果来自显式命令执行且绑定输入指纹。
- 静态页面嵌入构建后的数据，避免 file:// fetch 限制；每次提交构建 CI artifact，不自动提交生成文件。
- 使用固定 layer/order 布局和原生 SVG 连线，无大型图框架/CDN；界面状态同时有文字、颜色与细节证据。
- 显式执行或回放的检查 gate 返回0表示声明检查全部通过且结构有效；默认不执行的构建可以带 unknown 正常返回0。检查标签必须明确范围，尤其不得把纯参数测试称为真实渲染验收。
- 历史来源不是页面自动抓取对象；不从 History/Drive 复制正文，不为图表新增后台服务。
- 独立审查复现了 Map 的额外输入未绑定风险：memory_root 可指向仓库外并在变化后仍回放旧 pass。Explorer 现已在调用 Map 前限制 context/memory/area 的实际读取路径，并要求参与同一源清单；原合成复现已独立确认被拒绝。此次没有更改 Map 本身的既有接口。
- 当前执行环境拒绝本地 Chromium 套接字，自动审查不允许提权；现有浏览器接口也禁止 file://。因此只能确认模板语法、DOM引用与数据契约，不能声称桌面/手机渲染或真实浏览器交互通过。
